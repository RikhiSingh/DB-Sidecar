Project: Feytra — AI-Powered Database Schema Intelligence Sidecar (Rust)

Vision
- Make databases easier to understand and use by providing AI-powered schema intelligence, Q&A, and advisor tooling as a sidecar service. Start with PostgreSQL; extend to MySQL and others later.

What Feytra is
- A sidecar service that runs on users' VMs/servers
- Captures and snapshots database catalogs (DDL)
- Canonicalizes DDL per object and computes stable hashes
- Creates vector embeddings of schema objects for semantic search
- Maintains a dependency graph and lightweight stats
- Provides AI-powered Q&A through natural language interface
- Exposes both CLI and REST API interfaces

Core Architecture (3 Pillars)

1. SIDECAR DEPLOYMENT
- Runs on users' VMs/servers alongside their applications
- Lightweight, resource-efficient service
- No proxying of live queries - operates out-of-band
- Configurable via environment variables
- Supports Docker deployment

2. DDL VECTORIZATION
- Snapshot database catalogs and extract DDL
- Canonicalize DDL (normalize whitespace, sort constraints, etc.)
- Generate embeddings for each schema object
- Store in local SQLite with vector search capabilities
- Support multiple embedding providers (local_stub, OpenAI)
- Maintain version history and change detection

3. AI-POWERED Q&A
- Natural language interface for database questions
- Vector similarity search to find relevant schema objects
- Semantic understanding of user queries
- Provide contextual answers about schema structure
- Support for relationships, indexes, constraints, etc.

v0.1 Goals (must-have)
- PostgreSQL-only support
- Sidecar deployment model
- DDL capture and canonicalization
- Local vector storage (HNSW)
- CLI interface with chat mode
- Basic schema Q&A capabilities
- Change detection via polling
- SQLite metadata storage

Non-goals (for v0.1)
- No live query proxying or capture
- No write SQL generation
- No external LLM calls by default
- No complex schema visualization

Architecture (crates)
- core: config, catalog (PgCatalogProvider), fingerprint (canonicalizer + Merkle), stats, graph, embed (EmbeddingProvider trait, LocalStub), vectors (VectorIndex trait, HNSW), repo (SQLite), jobs (bootstrap/refresh)
- api: Axum router, OpenAPI, v1 routes (optional)
- sidecar (bin): CLI with chat mode, init, refresh, serve commands

Data model (SQLite)
- objects(id TEXT PK, kind TEXT, qualified_name TEXT UNIQUE, canonical_ddl TEXT, hash TEXT, version INTEGER, changed_at TEXT)
- relations(src_id TEXT, dst_id TEXT, kind TEXT)
- schema_versions(version INTEGER PK, merkle_root TEXT, created_at TEXT)
- object_stats(object_id TEXT, metric TEXT, value TEXT, collected_at TEXT)
- embeddings(object_id TEXT, embedding BLOB, provider TEXT, dim INTEGER, updated_at TEXT)
- queries(object_id TEXT, normalized_sql TEXT, example BOOLEAN, added_at TEXT)

DDL Vectorization Process
1. Connect to PostgreSQL and snapshot catalog
2. Extract DDL for each object (tables, views, indexes, etc.)
3. Canonicalize DDL (normalize, sort, hash)
4. Generate embeddings using configured provider
5. Store in SQLite with vector search index
6. Maintain version history for change detection

AI Q&A Flow
1. User asks natural language question via CLI
2. Generate embedding for the question
3. Search vector index for similar schema objects
4. Retrieve relevant DDL and metadata
5. Format response with context and relevance scores
6. Provide helpful suggestions and examples

CLI Interface
- `feytra chat` - Main AI assistant (like Cursor for databases)
- `feytra init` - Initialize schema intelligence
- `feytra refresh` - Refresh schema data
- `feytra serve` - Start API server (optional)

Configuration (.env)
- DATABASE_URL: PostgreSQL connection string
- SIDECAR_DB: SQLite metadata database path
- EMBED_PROVIDER: local_stub (default) or openai
- VECTOR_BACKEND: hnsw (default) or qdrant
- EMBED_DIM: embedding dimensions (default 768)
- SAMPLE_ROWS: rows to sample for stats
- POLL_INTERVAL_SECS: refresh interval
- RUST_LOG: logging level

Deployment Options
1. Direct binary on VM/server
2. Docker container
3. Kubernetes sidecar
4. Local development

Key Design Choices
- Sidecar model: out-of-band, no critical path impact
- Local vector storage: HNSW for fast similarity search
- SQLite metadata: portable, no external dependencies
- Embedding providers: pluggable, local_stub default
- CLI-first: immediate value, API optional
- Change detection: polling-based with optional NOTIFY
